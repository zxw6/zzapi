接入说明

把你的模型编码、网关地址和用户密钥填进去，就可以直接调用。
5 分钟上手
1
拿到用户密钥

先在 API 密钥页面创建自己的 `sk-live-...` 密钥，后面客户端要用这个鉴权。

2
确认模型编码

进入套餐中心页面，先确认你已购买对应分组，再查看要调用的模型编码，例如 `gpt-5.3-codex`。

3
填写网关地址

把 `base_url` 填成你的网关地址加 `/v1`，不要填上游地址，也不要填官网地址。

公网配置示例

给别人远程调用时这样填 
model_provider = "api111"
model = "gpt-5.3-codex"
model_reasoning_effort = "high"
disable_response_storage = true
service_tier = "fast"

[model_providers.api111]
name = "api111"
base_url = "http://p783d68b.natappfree.cc/v1"
wire_api = "responses"
requires_openai_auth = true

本地配置示例

你自己本机测试时这样填 
model_provider = "api111"
model = "gpt-5.3-codex"
model_reasoning_effort = "high"
disable_response_storage = true
service_tier = "fast"

[model_providers.api111]
name = "api111"
base_url = "http://localhost:9988/v1"
wire_api = "responses"
requires_openai_auth = true

IDE 支持矩阵

看这张表就知道什么客户端能真改代码，什么只是聊天。
`gpt-5.4` / `gpt-5.3-codex`

优先走原生 `/v1/responses`。如果客户端本身支持 Codex/Responses 工具流，并且带工作区权限，就能持续自我分析、持续调用工具、持续改代码，直到模型自己返回 `completed`。

普通 OpenAI 兼容聊天插件

这类客户端通常只有对话能力，没有本地文件工具。即使模型很强，也大多只能给方案、写补丁建议，不能直接修改别人电脑里的代码。

服务端 Agent 回退模式

如果客户端不带本地工具，但你又想让网关代为读写服务器上的项目，可以走 `metadata.gateway_agent=true` 和 `metadata.workspace_root`。这时修改发生在网关服务端指定工作区，不是在对方本机。

结束条件

支持 agent 的客户端或模型不会因为输出了一句自然语言就自动结束；会继续根据工具结果推进，直到上游真正返回完成事件，或者遇到明确错误。

每一项怎么填

按这个说明填写最稳
model_provider

这是自定义提供商名称，可以随便起，但必须和下面 `[model_providers.xxx]` 里的名字一致。

model

这里填后台已经创建好的模型编码，不是模型名称。例如 `gpt-5.3-codex`。

base_url

填你的网关地址加 `/v1`。公网用公网地址，本地用 `http://localhost:9988/v1`。

wire_api

当前保持 `responses` 即可，不要随便改成别的。

requires_openai_auth

保持 `true`，表示客户端会读取 `OPENAI_API_KEY` 来发送鉴权。

用户还要设置什么

这一项最容易漏掉

如果配置里写了 `requires_openai_auth = true`，那用户本地还要设置环境变量：

$env:OPENAI_API_KEY="你的 sk-live-用户密钥"

例如：

$env:OPENAI_API_KEY="sk-live-xxxxxxxxxxxxxxxxxxxxxxxx"
不要填上游 key，这里要填你在本系统里创建出来的用户密钥，也就是 `sk-live-...`

服务端 Agent 示例

                            当上游没有稳定触发本地改码时，可以直接走网关内置读写工具。
                        

                        
这不是 MCP 缺不缺的问题，而是显式告诉网关：这次 `Responses` 请求要进入服务端 agent 模式，并指定允许读写的工作区。

                        
curl http://localhost:9988/v1/responses ^
  -H "Authorization: Bearer sk-live-xxxxxxxxxxxxxxxxxxxxxxxx" ^
  -H "Content-Type: application/json" ^
  -d "{
    ""model"": ""gpt-5.3-codex"",
    ""stream"": false,
    ""metadata"": {
      ""gateway_agent"": true,
      ""workspace_root"": ""E:/project-ai/Test""
    },
    ""input"": [
      {
        ""role"": ""user"",
        ""content"": [
          {
            ""type"": ""input_text"",
            ""text"": ""在 TestApplication.java 里加一个 hello() 方法，然后告诉我具体改了哪里""
          }
        ]
      }
    ]
  }"

                        

                            `gateway_agent=true` 用来强制走网关内置 agent；`workspace_root` 用来指定允许读写的项目根目录。
                        

                    


                    

                        

                            
最容易填错的地方

                            遇到报错先检查这里
                        

                        
    
                            
  • `model` 填错，必须和后台模型编码完全一致。
    • 
                            
  • `base_url` 填成了上游地址或官网地址，正确写法应该是你的网关地址。
    • 
                            
  • 漏掉 `/v1`，导致接口地址不完整。
    • 
                            
  • 没有设置 `OPENAI_API_KEY`，客户端发起请求时就会鉴权失败。
    • 
                            
  • 把上游 key 当成用户 key 使用，结果会直接失败。
    • 
                            
  • 如果想让网关代你读写项目文件，请在请求里带上 `metadata.gateway_agent=true` 和 `metadata.workspace_root`。
    • 
                            
  • 如果别人用的是普通聊天型 IDE 插件，没有本地工具权限，就算接的是 `gpt-5.4`，也很难像官方 Codex 一样直接改他本机代码。
    •
